# 推荐结果可解释性标准化问卷模板

> 状态：待真人填写。本文档仅定义问卷设计、计分规则和采样要求，不包含任何真实受访者数据，不作为达标证据。

> 系统状态：已实现匿名邀请码、Q1-Q8 在线填写、敏感信息拦截、重复提交控制、原始 CSV 导出和自动汇总。当前仍无真人答卷，因此不能声明达标。

## 1. 使用目的

本问卷用于验证“推荐结果可解释性业务人员理解度 >= 90%”。被测对象应为真实银行业务、风控、运营、合规或科技人员。问卷结果必须来自真实填写记录，不能由模型、脚本或开发人员伪造。

## 2. 受访者要求

- 建议样本量：不少于 30 人；正式验收建议不少于 50 人。
- 角色覆盖：业务主管、风控经理、产品经理、运营管理人员、合规人员、数据分析或科技人员。
- 场景覆盖：客户营销、贷前风控、贷后预警、运营管理等至少 3 类场景。
- 每名受访者至少查看 2 个推荐样例，样例应包含推荐模型、推荐理由、证据卡片、数据缺口、合规提示和报告摘要。

## 3. 评分量表

所有封闭题使用 5 点 Likert 量表：

| 分值 | 含义 |
|---:|---|
| 5 | 非常同意 / 非常清楚 |
| 4 | 比较同意 / 基本清楚 |
| 3 | 一般 / 需要部分解释 |
| 2 | 不太同意 / 较难理解 |
| 1 | 完全不同意 / 无法理解 |

理解度判定：单题得分 >= 4 视为“可理解”。综合理解度 = 所有核心题中得分 >= 4 的作答数 / 核心题总作答数。

## 4. 核心题目

| 编号 | 题目 | 维度 |
|---|---|---|
| Q1 | 我能理解系统为什么推荐这些模型。 | 推荐理由清晰度 |
| Q2 | 推荐解释能够对应我的业务需求，而不是泛泛而谈。 | 需求相关性 |
| Q3 | 解释中引用的证据、标签、评分拆解能帮助我追溯推荐依据。 | 可追溯性 |
| Q4 | 我能理解推荐模型的适用边界和不适用条件。 | 边界理解 |
| Q5 | 我能理解使用这些模型所需的数据条件和数据缺口。 | 数据要求理解 |
| Q6 | 合规提示、人工复核提示和风险边界表达清楚。 | 合规可理解性 |
| Q7 | 多模型组合流程的输入输出关系和执行顺序清楚。 | 组合方案理解 |
| Q8 | 报告摘要足以支持我向同事或管理者说明推荐结论。 | 汇报可用性 |

## 5. 开放题

1. 哪一部分解释最有助于你理解推荐结果？
2. 哪一部分解释仍然不清楚或需要补充？
3. 如果要在真实业务中使用，你最担心的风险是什么？
4. 你希望系统增加哪些对比、证据或导出能力？

## 6. 数据记录字段

每条问卷记录至少应包含：

- `response_id`：匿名响应编号。
- `submitted_at`：提交时间。
- `department`：部门类别，不记录具体个人身份。
- `role`：岗位角色。
- `scenario_id`：被测业务场景。
- `sample_id`：被测推荐样例。
- `answers`：Q1-Q8 的 1-5 分。
- `open_feedback`：开放题文本。
- `consent_confirmed`：是否确认匿名用于评估。

禁止采集真实客户信息、身份证号、手机号、银行卡号、内部账号、生产系统密钥或任何银行敏感信息。

## 7. 达标计算

```text
core_answer_count = 受访者数 × 每人样例数 × 8
understandable_count = 核心题得分 >= 4 的作答数
comprehensibility = understandable_count / core_answer_count × 100%
```

达标条件：`comprehensibility >= 90%`，且每个角色类别至少有 1 名受访者。若某一维度低于 85%，即使整体达标，也应列为改进项。

## 8. 结果呈现

正式报告应同时给出：

- 总体可理解率。
- 各维度平均分和可理解率。
- 各角色/场景的分布。
- 低分题目归因。
- 开放题高频反馈摘要。
- 明确声明数据来源是真人问卷、LLM-as-Judge 开发评估，还是合成占位数据。

## 9. 系统采集流程

1. 评估负责人运行 `scripts/create_survey_campaign.py` 创建活动，明文邀请码只写入 `data/surveys/invitations/*.private.csv`，该目录不进入 Git。
2. 受访者在真实推荐结果页面点击“评价推荐解释”，输入活动编号和一次性邀请码。
3. 每人至少评价2个不同推荐样例；同一样例重复提交和超额提交会被拒绝。
4. 管理员通过 `/api/v1/surveys/campaigns/{campaign_id}/summary` 查看统计，通过 `/export.csv` 导出匿名原始答卷。
5. 软件只计算阈值，不验证真人身份；即使 `metric_threshold_met=true`，`formal_evidence_verified` 仍为 false。必须附真实人员名单、签字或可核验评审记录后，才能在答辩材料中声明正式达标。
6. 自动化或浏览器验收必须使用 `acceptance_test` 活动模式；其答卷标记为 `automated_acceptance_test_non_evidence`，永远不能触发真人指标达标。
