# 5 分钟演示脚本

## 演示目标

用 5 分钟证明系统不是单纯指标脚本，而是一个可运行的银行模型市场智能推荐助手：

- 业务人员能用自然语言提需求。
- 系统能解析需求、推荐模型、解释依据、提示数据缺口。
- 系统能组合多个模型并给出脱敏执行结果。
- 系统能生成报告、审计访问、展示合规边界。
- 指标、鲁棒性、Docker 启动和 API 端到端验收均有证据。

## 演示前准备

### 本地运行

```powershell
$env:PYTHONPATH='backend'
python -m uvicorn app.main:app --app-dir backend --host 0.0.0.0 --port 8000
```

另开终端：

```powershell
cd frontend
npm install
npm run dev
```

浏览器打开：`http://localhost:5173`

### Docker 运行

```powershell
docker compose up --build
```

如果前端端口 3000 被占用：

```powershell
$env:FRONTEND_PORT='3001'
docker compose up --build
```

### 证据命令

```powershell
python scripts\run_official_eval.py --all
python scripts\smoke_api.py
python scripts\check_no_secret_leak.py
```

## 5 分钟讲解节奏

### 0:00-0:40 开场定位

讲法：

> 我们做的是银行模型市场智能推荐助手。它解决的问题是：业务人员知道自己要做贷前风控、客户营销或运营管理，但不知道模型市场里哪个模型适合、需要哪些数据、能输出什么、风险边界在哪里。系统把自然语言需求转成模型语言，再基于模型资产库、标签、图谱、数据缺口和合规规则给出可追溯推荐。

同时点明边界：

> 当前没有接入真实银行生产模型市场 API，所以调用部分使用本地 demo adapter 和脱敏结果；但 real/http adapter、权限、审计、错误处理和 Docker 部署链路已经具备。

### 0:40-1:40 路径一：县域新客首贷营销

输入：

```text
我想筛一批县域新客，做首贷营销，最好能给出转化概率高的名单。
```

操作：

1. 点击解析需求。
2. 展示领域 `customer_marketing`、客群、输出、数据条件、标签。
3. 点击生成模型推荐。
4. 展示 Top5，重点看 Top1 `县域新客首贷转化预测模型`。
5. 展示推荐理由、评分拆解、证据卡片和数据缺口。

讲法：

> 这一步展示业务语言到模型语言的转换。系统不是简单关键词搜索，而是把首贷营销拆成客群、转化概率、名单输出、数据需求和合规边界，再给出推荐理由和证据。

### 1:40-2:30 路径二：农户小额贷款贷前风控

输入：

```text
帮我做农户小额贷款的贷前准入风控，最好能识别欺诈风险并给出额度建议。
```

操作：

1. 解析需求。
2. 展示智能澄清问题和数据条件。
3. 生成推荐。
4. 生成组合方案。
5. 展示反欺诈、准入评分、额度测算等节点，以及 IO 兼容性。

讲法：

> 单个模型通常解决不了完整贷前流程，所以系统会推荐组合方案。组合不是硬拼，而是检查每一步的输入输出、节点能力和数据缺口。

### 2:30-3:15 路径三：对公贷款贷后预警

输入：

```text
我想提前发现对公贷款可能逾期的客户，并给客户经理一个预警名单。
```

操作：

1. 解析并推荐。
2. 展示违约概率、预警、贷后相关模型。
3. 切换解释模式或查看报告。

讲法：

> 这一路径用于展示风控类输出、贷后边界和人工审核提示。系统会强调预警结果仅供内部风控使用，不能替代审批或处置决策。

### 3:15-4:00 路径四/五快速扫过

路径四：

```text
网点客流波动比较大，希望预测高峰时段并辅助排班，减少客户等待。
```

讲法：

> 这个场景展示运营管理。官方 60 个模型里没有精确网点客流模型，因此官方主榜会返回最近似官方模型并明确低匹配；页面下方可在独立的 Demo 参考区展示精确网点客流候选，但它不属于官方榜单，不计入官方指标或组合推荐。

路径五：

```text
请帮我识别高价值客户流失风险，输出需要重点挽留的客户名单和跟进优先级。
```

讲法：

> 这个场景展示客户留存和高价值客户经营，系统会推荐流失预测和价值评估相关模型。

### 4:00-4:35 报告、调用和合规

操作：

1. 点击生成报告。
2. 展示报告中的需求、Top 模型、组合方案、数据缺口、合规提示。
3. 如时间允许，展示模型调用结果表格和 CSV 导出。

讲法：

> 推荐不是停留在卡片上，而是进入报告和结果工作流。模型结果是脱敏样例，字段里会标记 demo data、使用边界和合规提示。

## 演示注意事项

- 不要说已经接入真实银行模型市场 API；当前是 demo adapter + real/http adapter 待配置。
- 不要说已经 live 调用 GLM；除非现场已经安全注入 `LLM_API_KEY` 并跑通 smoke。
- 不要把 synthetic dry-run 数据称为 LLM 生成数据。
- 如果端口 3000 被占用，使用 `FRONTEND_PORT=3001`。
- 如果评委问“demo 模型怎么处理”，回答：官方 60 模型构成默认主榜；105 个 demo 模型默认只在独立、明确标注的参考区展示，不与官方主榜混排，不计入官方指标、版本榜单和组合推荐，也不作为官方目录缺失时的兜底。
