## 1. 评测目标

本报告对比两套评估体系的关键指标：

- **官方评测（official_60）**: 基于竞赛数据集中的 60 个官方模型，在验证集（64 条 query）和测试集（62 条 query）上进行关键词匹配推荐引擎的 TopK 命中率评估。
- **旧 Baseline（105 模型）**: 基于早期 105 个模拟模型数据集，在 110 条样本 query 上进行的多维度评估，涵盖意图识别、标签提取、TopK 命中、解释可理解性和组合编排。

**对比目的**: 量化两套评估体系下的模型推荐性能差异，识别官方评测集的改进空间和潜在风险。

## 4. 失败归因

### 4.1 旧 Baseline 失败归因

旧 Baseline 共 105 条 query，Top5 命中率仅 32.38%，约 **71 条 query** 在 Top5 范围内未命中目标模型。失败原因主要包括：

- **意图分类错误**: 旧 Baseline 依赖的意图识别模块准确率仅 67.27%，大量 query 被分到错误的意图类别，导致推荐方向偏离。
- **标签提取不完整**: 标签 avg_recall 仅 0.3619，大量相关标签未被提取，削弱了匹配信号。
- **模型元数据覆盖不足**: 旧 105 数据集的模型描述不够精细，关键词匹配引擎难以区分相似模型。

### 4.2 官方评测失败归因

官方评测共 **19 个失败 case**（含验证集和测试集），归因分布如下：

| 归因类型 | Val | Test | 合计 | 占比 |
|---|---|---|---|---|
| confused_model（模型混淆） | 11 | 6 | **17** | **89.5%** |
| business_scenario_mismatch（业务场景不匹配） | 0 | 1 | **1** | **5.3%** |
| unknown（无法归因） | 0 | 1 | **1** | **5.3%** |
| **合计** | **11** | **8** | **19** | **100%** |

**主要失败模式**:

1. **模型混淆（89.5%）**: 推荐了名称或关键词高度相似但业务范围不同的模型。
   - 典型例子: "收单商户贷款营销模型" 与 "收单商户流失预测模型" 混淆；"理财产品综合评价模型" 与 "贷款产品综合评价模型" 混淆。
   - 根本原因: 当前关键词匹配缺乏场景级语义理解，难以区分同名不同业务的模型。

2. **业务场景不匹配（5.3%）**: 极少数 query 的推荐结果与业务场景明显不匹配。
   - 例如: query 关于"房贷申请人风险评估"，Top1 推荐了垒小户准入评分卡。

3. **无法归因（5.3%）**: 1 条 query 的失败原因不明确，需进一步人工分析。

## 5. 风险与建议

### 5.1 当前风险

1. **模型混淆是高优待修复项**: 89.5% 的失败归因于模型混淆，说明当前推荐引擎在细粒度区分方面能力不足。
2. **旧 Baseline 与官方评测差距过大**: 旧 Baseline 的 Top5 命中率仅 32.38%，无法作为官方评测的性能参考基线。两套体系在数据集、推荐引擎、评估维度上差异显著。
3. **评估维度不完整**: 官方评测目前仅覆盖 TopK 命中率，缺少意图准确率、标签提取质量、解释可理解性和组合编排质量的评估。
4. **测试集仍有 2 条完全未命中**: 测试集 Top5 命中率 96.8%，存在 2 条 query 完全无法推荐到目标模型。

### 5.2 改进建议

1. **引入场景级匹配**: 在关键词匹配基础上加入业务场景分类信号，减少同名不同业务模型之间的混淆。
2. **补充多维评估**: 将旧 Baseline 的意图准确率、标签提取、解释评估等维度迁移到官方评测集，形成更全面的评估看板。
3. **修复业务场景不匹配**: 针对 "business_scenario_mismatch" 类型，增加 query 场景解析和场景-模型映射规则。
4. **人工分析 unknown 失败**: 对 1 条 unknown 失败 case（test_0018）进行人工审查，确认根因。
5. **建立统一基线**: 将官方评测集的当前结果作为新基线，后续每次推荐引擎更新后重新评估并记录变化。
